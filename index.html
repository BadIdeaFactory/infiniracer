PROMPT

ok I don't like the ramps, keep this version for reference but rollback and add power ups on the course that make the repellent effect of the side of the course stronger, during this period have the vehicle flash

CHANGES

  • Rollback: ramps + airborne physics dropped from latest/; v015 stays in the snapshot folder as the "we tried ramps" reference. Codebase is back to the v014 baseline before layering the new feature
  • Power-ups: sparse pickups every 1500–2600 units (deterministic from worldSeed). Visual: a magenta wireframe hexagon rotating slowly at phase × 1.2, with a pulsing white phosphor core dot — clearly distinct from track (cyan) and scenery (amber)
  • Pickup detection: when the car centre is within POWERUP_RADIUS = 24 of an unpicked one (along-track + lateral together), the pickup is marked taken and car.boostT = 5 seconds
  • Boost effect: while car.boostT > 0, edge repulsion is multiplied by 3.0× (max push 620 → 1860 u/s) — well above MAX_SPEED, so the edge becomes a near-soft-wall you can't easily punch through. Returns to baseline when the timer expires
  • Vehicle flash: while boost is active, body / cockpit / wheel colours switch to a magenta-tinted palette at ~6 Hz via (Math.floor(phase × 12) & 1). Square wave gives a sharp on/off blink that reads as "powered up" rather than a soft glow
  • commitReset() clears the powerups array + boost timer; trimWorld() drops pickups (taken or not) once they're well behind
  • Fix pass: the "power-ups disappear" bug — four call sites computed track indices as Math.floor(s / SEG_LEN), but after trimWorld() splices old segments off the front, track[0].s is no longer 0 so that math points at the wrong row (or clamps to the last segment, making the hexagon snap to the end of the visible track). Added a trackIndexAt(s) helper that uses track[0].s as the base offset; rewired scenery placement, power-up gen, power-up render, and distance markers through it
  • Hexagon visual radius 14 → 21, pickup hit radius 18 → 24
